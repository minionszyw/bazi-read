# AI Agent 命理分析指南

技能负责执行顺序，本指南负责分析方法和输出约定；[统一模板](../examples/output.template.json)只规定报告骨架。
引擎提供静态可计算事实，分析时依选定古籍论法解释其配合，不把两者混称为自动断命结果。

## 1. 分析前核对

确认生辰、历法、时区、实际排盘规则及引擎结果一致；关键资料不明确或存在交界歧义时，先解决再分析。
输入解析和调用按[技能文档](../.agents/skills/bazi-read/SKILL.md)执行。本指南只说明读取什么资料及如何解释。

|分析目的|引擎字段|
|---|---|
|核实时间与规则|input、rules、time、warnings；需要时trace|
|原局、根气与十神|natal四柱及hidden；以natal.day为日主参照|
|月令深浅|season前后十二节、交节时刻及入节时长|
|结构配合|顶层relations，仅说明字面关系，不证明合化|
|大运|luck中的顺逆、起运年龄、交运时间及各步概览|
|具体年份与月份|analysis.annual、analysis.periods及按需展开的analysis.monthly|
|辅助论法|auxiliary中的纳音、旬空、胎元、命宫、神煞及两种十二长生参照|

## 2. 原局分析

以《子平真诠》的月令格局论法为主线，配合其他古籍；这是项目整理顺序，不是各书共有的唯一次序。
每条关键判断直接记录：结论、实际排盘依据、所用论法、古籍出处、成立条件与未决因素。事实与解释分开，不能只罗列术语。

### 日干与月令

先识别日干，再核对月支、藏干、透干及season前后节。区别月令本气、藏干透出与其他柱透干：例如庚透并不等于辛透，阴阳十神要分别处理。月令格局提供主线，但不能仅看月支就结束全局分析。

记录月令所藏哪些干、哪些有同干透出、是否受其他干支作用；未找到适合论法时保留候选，不随意归入特殊格。入节时长可描述季节深浅，不能伪装成古籍一致认可的分日司令表。

### 力量与根气

分别检查日主与财官杀印食伤比劫，不只评日主一个对象。

- 得令：季节对该五行的条件，不等同字数最多。
- 通根：天干在何柱藏干有同干或同五行支持；本气、余气的权重须解释，不能用藏干排列直接当力量比例。
- 透藏：地支所藏能否由天干表达，位置是否相邻，有无争合或阻隔；合冲存在并不自动消灭藏干。
- 生扶、泄耗、克制：先标作用来源，再考察作用者自身是否有根有力，以及作用链是否受到制约。
- 反证：印透未必足以扶身，财多未必有力，日主有根也未必旺。十二长生仅作所选论法的辅助，明确按日主还是各干自坐。

结论用“哪些条件支持、哪些条件限制”表达；不足时在uncertainties中说明未决条件，不制造强弱百分比。需要比较不同假设时并列条件，不让假设成为已知事实。

### 格局与成败救应

读《子平真诠》用神及成败救应相关篇，明确这里“用神”的月令语境。
先列格局候选所需条件，逐一检查原局配合、日主承受条件、清浊及混杂因素，再问有无损伤、补救是否实际有力。
相同十神组合因月令主线不同，不能只按字面标签互换名称。不要把“财官印俱见”直接当三者皆可用。

从格、化格等特殊判断须独立列必要条件与反证；若同局有显著逆势或支持未尽核对，先保留普通格局解释，不以“看起来偏枯”直接判从。列出天干五合或三会不等于化气成功。

### 寒暖燥湿与气势

以《穷通宝鉴》日干、季节条目作条件性参考，不把每条季节取用当所有命局的固定处方。实际寒暖燥湿要结合全局，节令不是出生地当天气象，引擎也没有测量湿度温度。某五行未出现只能作为观察，不能单凭“无火”便确立调候用火；提出候选时说明寒暖燥湿的实际论法依据和相反条件。

气势分析记录可能的生克链、汇聚点与受阻位置，例如某五行能否承接上游并引向下游；区分“字面上有生克路线”与“论法上足以流通”。对于枯燥、寒湿、一气等用语说明判断条件，不能直接变成生活事件。

### 喜忌及论法协调

分别写：格局所用及救应、扶抑需要、调候需要、气势流通需要。若方向一致，说明共同条件；若冲突，列优先考虑的原因、适用范围与未决问题，不把多个“用神”强行合成一个字。
喜忌可能随大运条件变化，不能把暂定五行推广为固定幸运色、配饰、居住方向或投资指令。未充分论证时应保留未定。

## 3. 岁运分析

先固定原局判断的条件，再看大运改变哪些配合，最后加入流年和必要的流月。读关系时合并顶层relations、当年analysis.periods对应段及流月对应段；某层未重复列出的原局关系不是消失。

- 大运概览只含干支和时间，不含完整关系。细论某一步时，可按该步开始时刻所属立春年重新调用，选匹配区间；不能将一个年份推广为整步十年的结论。
- 分清原局—运、原局—年、运—年及多方组合。记录“原局条件→岁运变化→可能影响主题→成立条件/反证”，不从某个冲直接跳到具体事件。
- analysis.periods按交运时刻分段，区间左闭右开；首次起运前luck为null，不自行补小运或前一步大运。
- 流月按节月起止，不以农历初一代替。跨交运月份按对应periods分别解释。
- 大运前后五年等解释法若采用，注明出处与条件，不当作引擎事实。引擎没有给出的关系若由分析者推导，明确标为分析者推导。

## 4. 分项与持续问答

|主题|分析线索与边界|
|---|---|
|性情|结合十神配合及制化，不从日干或单个十神定人格|
|学习|考察印、食伤及整体配合，不见印就断学历、考试名次|
|事业|沿格局、力量与岁运条件解释，不指定唯一行业、职位|
|财务|看财与日主、食伤官印比劫的配合，不以财多断富或以见财断获利|
|婚恋|日支及选定传统论法的对应十神只是线索，见冲不直接断离异；现实关系结构以用户说明为准|
|六亲|宫位、十神与现实背景合看，不把克制关系写成亲属确定遭遇|

每项先说排盘依据，再说解释及不足。默认不增加疾病、寿命、灾祸栏目，也不输出诊断、确定日期或具体投资指令。

|追问类型|处理|
|---|---|
|解释已有结论|复用有效资料，说明依据和推理桥梁，不重排整份报告|
|新年份或月份|按需调用相应analysis_year/include_monthly，保留仍有效的原局判断|
|修改出生资料或规则|重新核对原局，说明改变的字段，重建受影响的力量、格局、喜忌与岁运判断，不沿用旧日主十神|
|新增现实经历|标为用户提供的背景，可检验解释条件，但不倒改规则迎合经历|
|缺少必要信息|自然语言补问，结构化澄清时填写questions，不索取无关资料|

解释已有判断时，围绕实际排盘依据、所用论法和条件展开；只补充当前问题所需的分析，不重发完整报告。

## 5. 报告组织

按[输出模板](../examples/output.template.json)依次组织 `input → chart → natal → fortune → domains`。完整报告为一个JSON对象，不加Markdown围栏或JSON外说明；模板是空骨架，不能当作引擎输入或已完成报告。

|部分|内容与组织方式|
|---|---|
|name、case_id、context|标明本次分析对象、实际排盘规则、分析年份和未决项；资料识别与修订按技能处理|
|input|用户原文、规范化资料、字段来源及未决项|
|chart|真实引擎结果；多年份调用可填结果数组，不手造干支，也不在后文重复复制完整排盘|
|natal|按day_master、month_command、strength、pattern、climate、flow、preferences组织日主、月令、力量、格局、寒暖燥湿、气势与喜忌，各组为判断记录数组|
|fortune|overview概括各步大运；years按年份和实际交运区间分段解释，保留对应start/end，避免把交运前后混作同一阶段|
|domains|性情、学习、事业、财务、婚恋、六亲分别填写判断记录；资料或论证不足时说明未定|
|questions|影响本次分析的必要补问，无则为空数组|

关键判断采用模板natal.day_master中展示的结构，其他原局分组及岁运、分项中的判断复用同一结构：

|字段|填写要点|
|---|---|
|conclusion|直接给出本条结论，区分已观察事实与条件性解释|
|basis|列实际排盘field和observation，例如natal.day.ganzhi；多盘时注明年份或规则分支|
|method|说明从依据到判断所用的论法，不只罗列术语|
|sources|随判断列书名、版本、篇章和核验状态；未核实的page、quote填null；项目归纳注明synthesis|
|conditions|写成立条件、适用范围、反证或救应，不为填满模板而编造|
|uncertainties|写未决因素、不同论法及规则敏感性；不足时保留未定，不强行给喜忌|

report_type为initial或clarification；status为complete、partial或needs_input。complete只表示报告流程完成，不表示每个判断都已确定或预测必然准确。
资料不足时先补问；若输出结构化澄清，只填写相关资料和questions，其余为null或空数组。普通追问用自然语言单独解释，不加入完整报告。

### 保存前审查

- **结构与事实**：JSON可解析，chart与真实引擎输出一致，原局、十神、当前大运和流年区间相符；生辰更正后不混入旧结论。结构完整不代表分析论证充分。
- **边界与方向**：涉及生时误差时，核对哪一方向、相差多久才会跨哪个交界；误差作用在民用钟点还是太阳时须说清，不能把单方向阈值写成任意方向都适用。
- **判断条件**：力量、格局、调候和喜忌均有理由及必要条件；“缺少某五行”或“某关系命中”不足以独立推出结论。保留合、克等并见时的作用取舍，不把每种可能作用都当成充分实现。
- **依据定位**：field尽量指向具体柱或区间。列表可写analysis.periods[0].luck；多个柱位分别列basis，不用natal.year/month等合并简写。多年份、多盘须注明对应对象，不恢复全局编号或复杂引用协议。
- **来源核验**：verified_scan只表示核对过相应古籍内容，不表示古籍验证了个人命局结论。分清原文论法和个人应用，归纳部分注明分析者推导；不能凭同一组页码支持所有延伸判断。
- **表达质量**：未决因素写本条具体的限制，不反复复制“缺少现实背景”等通用句。已支持的判断直接说明，尚未定的部分具体指出，避免把整份报告写成没有主线的保留意见。


### 保存后解盘

参考《子平真诠》〈论用神格局高低〉对配合有情、有力的辨析，〈论生克先后分吉凶〉对位置与先后的讨论，以及〈论行运〉将运中干支放回原局统观的方法。以下讲解顺序和白话表达为项目归纳，具体分析方法见第2—4节。

保存报告后，在同一轮对话中先提供文件链接，再直接用自然语言完整但聚焦地解读。以已保存报告为依据，不等用户再次要求，也不把JSON逐字段朗读。

1. **概括原局主线**：直接给出最重要的判断及决定它的日干、月令和关键条件，不重复罗列全部排盘资料。区别排盘事实、选用论法和条件性解释。
2. **讲清关键配合**：围绕力量、格局及成败救应，落实到具体干支和柱位，解释谁支持谁、谁制约谁，以及哪些作用决定主要判断。配合是否有助于所论格局、作用者是否有根有力，要分别说明；位置、先后及合克并见时的取舍也须交代，不能只报格局和强弱标签。
3. **说明喜忌取舍**：承接关键配合解释喜忌，分别交代格局、扶抑、调候及气势流通的需要。方向不一致时，说明主判断、优先理由和适用条件；未决条件须保留，无须在每段重复相同限制。
4. **解释岁运变化**：说明当前大运、目标流年扶助、损伤或改变了原局哪个条件，有无成格、变格或救应的条件，再解释哪些主题值得关注。落实到具体干支及配合，不因同属一种五行便作相同判断，也不凭单个合冲直接断事。交运年分别讲明前后阶段，不默认展开所有大运或流月。
5. **落到分项含义**：围绕性情、学习、事业、财务、婚恋、六亲，按“命局依据→传统解释→现实中可能体现的主题→适用条件”讲清重点。同源判断合并表达，资料不足处明确说明，不为覆盖栏目而重复套话。

术语首次出现时用普通语言解释，形成“主要判断→依据→具体含义→适用条件”的连贯叙述。解盘允许按内容使用短标题和列表，不采用完整报告的JSON形式，不固定字数。
只解释报告已支持的内容，不临时增加无依据的职业、金额、婚期或必然事件；若发现实质错误，先说明问题，按既有报告更新规则处理，不悄悄改写旧档。

解盘和后续问答仅在会话中呈现，不新增报告字段、文件或问答日志。后续问题只补充相关内容，不重新讲完整份报告。

### 现代约定与适用范围

- 公农历采用现代历法回推，不是复原历史授时历。海外农历先转公历日期标签，再配当地钟表时间，时区另指定。
- sxtwl节气JD在适配层按UTC+8表达解读后转UTC；年月交界比较同一绝对时刻，不能只修正出生钟点而移动节气。
- 默认立春换年、十二节换月；春节换年只是可选对照，月干仍从立春年干推算。00点换日的依据不单独证明晚子时必须借次日日干，两项分别配置。
