# bazi

面向 AI Agent 的八字排盘与命理分析工具，支持独立 CLI 排盘。

用自然语言提供出生资料，由本地引擎计算原局与岁运，Agent 依据古籍分析指南生成报告、讲解命盘，并接续追问。

**出生资料 → 排盘 → 分析报告 → 解盘 → 追问**

## 特性

- **对话分析**：解析出生资料，依次分析原局、岁运和性情、学习、事业、财务、婚恋、六亲。
- **本地排盘**：支持公历与农历输入，计算四柱、藏干、十神、节令、大运与指定流年，按需展开流月。
- **规则可查**：支持真太阳时、平太阳时和民用时间，明确换年、换月、换日及晚子时口径，可对照不同规则。
- **依据可追溯**：报告区分排盘事实、所用论法、古籍出处、成立条件及未决因素。
- **资料可复用**：使用统一 JSON 报告保存分析，支持多份出生资料与报告版本，继续追问时复用已有资料。

引擎负责可计算资料，Agent 负责命理解释；分析能力由技能、指南和模板组织。

## 快速开始

要求 **Python 3.10+**。进入项目根目录后，创建虚拟环境并安装：

```sh
python3 -m venv .venv
.venv/bin/pip install -e .
```

已有环境时可复用；Agent 会先检查依赖，仅在缺少时安装。安装完成后，可通过下面的 Agent 或 CLI 入口使用。

## Agent 使用

在能读取项目文件、执行本地命令的 AI Agent 环境中打开项目，让 Agent 按[技能文档](.agents/skills/SKILL.md)执行工作流，即可直接对话。

### 提供出生资料

提供性别、历法、出生年月日时分、出生地或经度，以及出生记录的时区；姓名可选。例如：

> 我叫小林，男，公历1990年5月17日14:30，出生地北京市东城区，时间记录为当时当地钟表时间，时区 Asia/Shanghai。请分析原局和今年的岁运。

Agent 核对资料后排盘，按指南分析日干月令、力量、格局、寒暖燥湿、气势及喜忌，再结合大运、流年完成分项分析。关键资料有歧义时先补问。

首次默认分析十步大运及当前立春年，完整报告保存为 `outputs/<case_id>.json`。返回文件链接后，Agent 直接用自然语言讲解原局主线、当前岁运和分项重点。

### 继续追问

> 刚才为什么这样判断事业？请结合命盘解释。

可继续讨论已有结论，也可指定其他年份或月份。追问单独用自然语言回答，不写入完整报告。

### 更新报告

> 请把小林明年的分析更新到报告，保留旧版。

明确要求更新时，另存为 `outputs/<case_id>-002.json` 等递增版本，保留旧文件。资料识别、复用和修订约定见[技能工作流](.agents/skills/SKILL.md#工作流)。

## CLI 使用

CLI 可独立计算排盘、对照规则和查询地点，结果以 JSON 输出到终端。

### 准备输入

将以下内容保存为项目根目录下的 `case.json`：

```json
{
  "birth": {
    "sex": "male",
    "calendar": "solar",
    "year": 1990,
    "month": 5,
    "day": 17,
    "hour": 14,
    "minute": 30,
    "longitude": 116.405285,
    "timezone": "Asia/Shanghai"
  },
  "rules": {
    "time_basis": "apparent"
  },
  "options": {
    "luck_count": 10,
    "analysis_year": 2026
  }
}
```

`luck_count` 为大运步数；`analysis_year: 2026` 指定分析2026立春年，并非自动选择当前年份。`case.json` 是排盘输入，完整报告模板用于 Agent 分析输出。
字段和可选规则见[排盘约定](.agents/skills/SKILL.md#排盘约定)。

### 执行命令

在项目根目录运行：

```sh
# 原局与指定年份的岁运排盘
.venv/bin/bazi chart --input case.json

# 对照时间和换日规则
.venv/bin/bazi compare --input case.json

# 查询出生地
.venv/bin/bazi places 东城区
```

CLI 提供排盘事实，命理分析、完整报告保存及解盘由 Agent 工作流完成。

## 限制与致谢

- **资料与精度**：出生公历年支持1900—2100，生时需准确到分钟；太阳时计算需要经度。计算结果的秒数不代表出生记录具有同等精度。
- **古籍与解释**：古籍扫描本按约定位于项目根目录外的 `../子平古籍/`，不随仓库提供。分析应区分原文、注文与归纳；报告属于传统体系的条件性解释，排盘正确和古籍有载不代表预测必然准确。
- **数据与环境**：地点表为近似坐标，来源、坐标系及再分发许可尚待确认；Agent 使用的模型及数据处理方式由实际运行环境决定。

历法计算依赖 sxtwl（BSD-3-Clause），时区数据由 tzdata 提供。感谢寿星天文历原作者许剑伟及 sxtwl 维护者。
古籍核验与计算口径的详细说明见[分析指南](docs/analysis.md#6-古籍依据与计算限制)。
